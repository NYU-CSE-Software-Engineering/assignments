# Project Evaluation Rubric

## I. Core Implementation & Technology
| Criterion | Exemplary (4) | Satisfactory (3) | Developing (2) | Unsatisfactory (1) |
|---|---|---|---|---|
| **Language & Framework** | The application is fully developed in Ruby on Rails and expertly utilizes advanced concepts/design patterns covered in the course. | The application is fully developed in Ruby on Rails and correctly uses the materials and design patterns covered. | The application uses Ruby on Rails but demonstrates significant gaps or misuse of core framework concepts and materials. | The application deviates from the required Ruby on Rails framework or is fundamentally non-functional. |
| **RESTful API & Backend Logic** | All proposed RESTful endpoints are implemented, fully functional, and exhibit highly efficient, clean, and robust backend logic. | All proposed RESTful endpoints are implemented and fully functional with correct, clear backend logic. | Most RESTful endpoints are implemented, but some are non-functional, or backend logic contains significant errors or is difficult to follow. | Few or none of the proposed RESTful endpoints are implemented or are non-functional, demonstrating a lack of core functionality. |

## II. Architectural & Quality Deliverables
| Criterion | Exemplary (4) | Satisfactory (3) | Developing (2) | Unsatisfactory (1) |
|---|---|---|---|---|
| **Database Integration & Schema** | The database schema is fully implemented, optimized, and flawlessly supports all application data models and complex relationships. | The database schema is fully implemented and correctly supports all application data models and relationships. | The database schema is mostly implemented, but contains minor inconsistencies, or key relationships are missing/incorrect. | The database schema is incomplete, or core data models and relationships are fundamentally broken or missing. |
| **Model Validation & Logic** | Model logic is robust, leveraging all necessary and advanced validations, filters, and custom methods to ensure data integrity and business rules. | Model logic includes all necessary validations and filters required to maintain data integrity and functionality. | Model logic is present but lacks some necessary validations or filters, leading to potential data integrity issues. | Model logic is largely absent or incorrect, failing to implement basic validations and filters. |
| **Frontend Interface** | Application features a functional, well-styled, and highly readable interface, using Bootstrap or a similar framework to enhance usability. | Application features a functional and readable interface, utilizing Bootstrap or a similar simple CSS framework. | Frontend is functional but uses only non-styled HTML views, or the use of styling is minimal/inconsistent, hindering readability. | Frontend is non-functional, making it impossible to demonstrate the application's core features. |
| **Deployment** | The application is successfully deployed on a live platform (e.g., Heroku, Render), is highly stable, and runs without error. | The application is successfully deployed and accessible on a live platform and runs correctly. | The application is deployed, but connectivity issues, frequent errors, or significant configuration problems prevent consistent access/functionality. | The application is not deployed or is completely inaccessible on a live platform. |

## III. Testing & Code Coverage
| Criterion | Exemplary (4) | Satisfactory (3) | Developing (2) | Unsatisfactory (1) |
|---|---|---|---|---|
| **Test Suite Implementation** | A comprehensive testing suite (RSpec/Cucumber) is implemented, and tests are highly targeted and follow TDD/BDD best practices. | A basic testing suite (e.g., RSpec) is implemented, ensuring the stability of critical backend functions. | The testing suite is minimal, covers only a few critical functions, or demonstrates poor test organization/quality. | No basic testing suite is implemented, or the tests that exist are non-functional or entirely meaningless. |
| **Test Coverage Target** | Combined code coverage is >= 90% and includes a strong balance of both TDD (RSpec) and BDD (Cucumber) tests. | Combined code coverage is >= 80%, meeting the minimum required target. | Combined code coverage is between 60% and 79%, falling short of the required minimum. | Combined code coverage is less than 60%, or the coverage report is not generated/provided. |

## IV. Version Control & Collaboration (Per Team Member)
| Criterion | Exemplary (4) | Satisfactory (3) | Developing (2) | Unsatisfactory (1) |
|---|---|---|---|---|
| **Branching & Pull Requests (PRs) - post TDD assignment (11/6/25)** | Team member created >= 4 non-trivial feature branches and >= 4 approved PRs, demonstrating an expert-level command of Git workflow. | Team member created >= 3 non-trivial feature branches and initiated/merged >= 3 PRs containing new feature code. | Team member created 1 to 2 non-trivial feature branches or initiated/merged 1 to 2 PRs. | Team member created 0 non-trivial feature branches or initiated 0 PRs. |
| **Code Review & Approval** | Team member acted as a reviewer and formally approved >= 4 Pull Requests submitted by teammates, providing detailed, constructive, and impactful feedback. | Team member acted as a reviewer and formally approved >= 3 Pull Requests submitted by teammates. | Team member acted as a reviewer/approver on 1 to 2 Pull Requests, or review feedback was minimal/non-existent. | Team member acted as a reviewer/approver on 0 Pull Requests. |

## V. Documentation
| Criterion | Exemplary (4) | Satisfactory (3) | Developing (2) | Unsatisfactory (1) |
|---|---|---|---|---|
| **README.md Quality** | README is a high-quality, comprehensive single source of truth that is flawlessly clear, concise, and includes all required sections and an insightful project overview. | README is a high-quality single source of truth that includes all required sections: Title/Description, Team/Roles, Setup Instructions, and Testing Instructions. | README is present but is missing one or more required sections, or instructions for setup/testing are vague or contain errors. | README is missing, incomplete, or fails to provide essential information for project setup and execution. |
